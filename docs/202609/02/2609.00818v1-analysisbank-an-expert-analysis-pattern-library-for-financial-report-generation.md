## 摘要
我们主张金融报告生成应在分析层面而非结构层面进行，即从数据衍生的洞察中组织内容，而非基于高层主题或章节。为此，我们提出AnalysisBank，它将专家报告提炼为可复用的分析库（Analyses），每项分析将数据信号、分析动作及其来源的专家片段配对。在推理时，AnalysisBank将输入信号与库条目匹配，并应用检索到的动作来撰写报告。对从550份专家报告中提炼出的分析进行的研究显示，其呈现重尾分布，涵盖47至52种信号类型，分属13种动作类型。在四个大语言模型骨干上的两个金融基准测试中，AnalysisBank将新颖、基于数据的洞察比例相较于结构级基线提升了1.7至3.7倍。向科学写作的迁移表明，这一区分具有超越金融领域的普适性。代码及提炼后的分析库见 https://github.com/yajingyang/AnalysisBank。

## Abstract
We argue that financial report generation should operate at the analytical rather than structural level, composing content from data-derived insights rather than high-level topics or sections. To this end, we propose AnalysisBank, which distills expert reports into a reusable library of Analyses, each pairing a data signal, an analytical move, and the expert span it was derived from. At inference time, AnalysisBank matches input signals to library entries and applies the retrieved moves to compose the report. A study of Analyses distilled from 550 expert reports reveals a heavy-tailed distribution of 47-52 signal types spanning 13 move types. On two financial benchmarks across four LLM backbones, AnalysisBank increases the proportion of novel, data-grounded insights by 1.7-3.7x over structural-level baselines. Transfer to scientific writing suggests that the distinction generalizes beyond finance. Code and the distilled Analysis library are available at https://github.com/yajingyang/AnalysisBank.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有金融报告生成方法大多在“结构层面”运作——只规定报告应覆盖哪些章节或主题，但不规定针对具体数据应做何种分析，导致模型默认生成泛泛的趋势描述和常规比率计算，而非数据真正值得的分析洞察。
- **提出新区分**：论文提出报告生成应在**分析层面**运作，即报告应组合“由数据信号触发的分析动作”产出洞察，而非组织高层话题。
- **处理难点**：(1) 数据信号与分析动作的配对空间巨大且呈重尾分布，稀疏的模式难以让 LLM 通过 prompt 或 fine-tuning 学会；(2) 自回归模型偏向高概率输出，难以调用尾部特殊性强的分析动作。
- **整体含义**：该工作主张通过外部化的、可复用的专家分析模式库来突破 LLM 的结构化默认行为，其范式也迁移到科学写作，暗示分析级范式具有跨领域的一般性。

### 2. 论文提出的方法论

#### 核心思想
- 将专家报告中的洞察反推为“数据信号 + 分析动作”配对，并把配对抽象为可复用条目（`Analysis`），在推理时与输入信号匹配并执行。
- 每条 `Analysis` 是三元组：
  - `data_signal`：无实体、无数字的抽象出发条件（检索用）。
  - `analytical_move`：可执行的指令性分析动作（执行用）。
  - `reference_text`：从专家报告中摘录的原始片段（示范与事实性锚点）。

#### 提取管线（四趟、离线构建静态库）
1. **Induce**：从专家报告原文中定位执行了特定推理操作的段落，作为 `reference_text` 候选。
2. **Generalize**：剥离实体、数字与时间引用，抽象出 `data_signal` 与 `analytical_move`，做行业无关性自检。
3. **Deduplicate**：基于 `data_signal` 嵌入的贪心单链接聚类合并冗余条目，保留最通用的 signal 与最完整的 move。
4. **Quality-filter**：对每条候选按可迁移性、可操作性、有据性三标准验证；失败者经有针对性改写重试或丢弃。

#### 推理管线（四阶段、各阶段均用同一骨干 LLM）
1. **信号抽取**：文本输入靠 LLM 检测 17 类基础信号并经事实核查；结构化数据由 Python 程序确定性计算技术指标。
2. **按类型检索**：每种信号类型贡献最优 `Analysis` 匹配，其余槽位由全局 top-k 补充；用余弦相似度在 `data_signal` 字段上匹配，并做同行业加分。
3. **独立执行**：每条被检索的 `Analysis` 独立执行其 `analytical_move` 于触发信号上，生成一条分析性 finding（含 reference_text 作示范）。
4. **合成**：由单次 LLM 调用将 findings 组织为围绕投资主题的报告，同时补充原始信号填充事实空缺。

- SciGen 上分析率与胜率最高，洞察率微低于 BoT，说明“尾部优势”在动作词汇更窄的领域奖励较低。

- **概念贡献明确**：清晰区分结构级与分析级报告生成，确立问题定位。

- **可复制性**：发布蒸馏库与代码，方便后续复现与扩展。

### 8. 不足与局限

- **库质量受源语料约束**：若源报告平淡或模板化，蒸馏出的分析动作无法超出源报告已有的深广度（论文在 Limitations 中自认）。
