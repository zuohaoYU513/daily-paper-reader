## 摘要
确保事实性仍然是高可信场景中部署大语言模型的关键挑战。现有的幻觉检测器通常在单一层级上运作：声明级方法提供可解释的事实单元，而跨度级方法定位无根据的文本。弥合这些视角代价高昂，因为重LLM流水线需要多次分解和验证调用，而模块化系统需要额外的声明到跨度对齐。我们提出Enoki，一个用于多层级幻觉检测的开放信息抽取框架。Enoki抽取文本锚定的关系事实，将其与证据验证，并将无根据的事实映射回幻觉跨度。这种共享表示使声明级验证和跨度级定位无需单独对齐即可实现。Enoki支持基于LLM、基于编码器和基于规则的抽取机制，通过通用接口平衡准确性和推理成本。实验表明，Enoki在使用更少资源的同时，与强声明级系统保持竞争力，并在细粒度跨度和实体级定位上取得优异性能。我们还发布了EnokiQA，一个具有对齐的声明级验证和跨度级定位注释的双粒度数据集。

## Abstract
Ensuring factuality remains a critical challenge for deploying LLMs in high-stakes settings. Existing hallucination detectors usually operate at a single level: claim-level methods provide interpretable factual units, while span-level methods localize unsupported text. Bridging these views is costly, as LLM-heavy pipelines require multiple decomposition and verification calls, and modular systems need additional claim-to-span alignment. We propose Enoki, an Open Information Extraction framework for multi-level hallucination detection. Enoki extracts text-anchored relational facts, verifies them against evidence, and projects unsupported facts back to hallucinated spans. This shared representation enables claim-level verification and span-level localization without requiring separate alignment. Enoki supports LLM-based, encoder-based, and rule-based extraction regimes, balancing accuracy and inference cost through a common interface. Experiments show that Enoki remains competitive with strong claim-level systems while using fewer resources and achieves superior performance on fine-grained span- and entity-level localization. We also release EnokiQA, a dual-granularity dataset with aligned claim-level verification and span-level localization annotations.

- **核心问题**：能否用**一种统一的中间表示**同时支持声明级可解释验证和跨度级精确定位，且资源开销低？

## 2. 方法论：核心思想与关键技术

### 2.1 核心流程（两阶段+投影）
Enoki 的完整流程为**事实抽取 → 事实验证 → 跨度投影**：

1. **事实分解（Fact Decomposition）**：用 OpenIE 风格后端将每个回答句子提取为免模式的关系三元组 `(subject, predicate, object)`（称为"事实"）。强制**文本锚定约束**：幻觉相关的论元必须保持对齐到回答中的原始跨度。
2. **增量事实构造（Incremental Fact Construction）**：
   - 将相关的事实组织为"自包含的细化"组，每一步引入少量新信息（如 `Enoki | is | mushroom` → `Enoki | cultivated in | northern China`）。
   - 验证阶段可区分"被支持的基础事实"和"不被支持的具体细化"，误差被定位至**新增的 delta 片段**（例：`northern`）。
   - 这一机制是 Enoki 跨越声明级与跨度级的关键。
3. **事实验证（Fact Verification）**：
   - 将每个三元组转为文本假设，用 NLI 风格的验证器打分。
   - 长上下文被切为片段（含一句重叠），对每个事实取**跨所有块的最大蕴含分数**，实现长证据下的局部匹配。
   - 将未通过验证（neutral+contradiction 概率 > 0.5）的事实判定为幻觉，其对象 delta 投影为幻觉跨度。

### 2.2 事实抽取后端（三种实现机制）
实现同一规则/接口，以权衡精度与效率：
- **Enoki-LLM**：基于 CycleOIE 的高性能提示，通过GPT-OSS-120B等LLM增加3条**增量分解准则**（如增量参数跨度、复合参数拆分等），获得最细粒度的输出。
- **Enoki-Rule**：纯规则/依赖解析方法，包含 35 条规则，在 spaCy en_core_web_trf 句法解析上运行。经过两阶段（OpenIE6/LSOIE 引导、EnokiQA 细调）的**智能Agent驱动精化循环**迭代产生，规则可插拔、自包含。
- **Enoki-Encoder**：改良自 **OpenIE6 的 IGL**（Iterative Grid Labeling）架构，编码器升级为 **ModernBERT-large**；采用**置换不变的匈牙利匹配损失**（受 DETR 启发），解决了多行递增抽取中逐行交叉熵对行顺序过于敏感的问题，已证实为训练显著更为稳定。

### 2.3 可选预处理
- 利用 FastCoref 对回答进行去上下文化，将代词引用替换为先行词，作为可选开关（非默认启用）。

### 2.4 核心创新
- **共享文本锚定事实**同时服务验证和投影（消除了单独对齐模块）。
- **增量事实组合 + 严格细粒度构造**保证每个参数（含修饰语、时间状语等）都被显式表达，增强了遗漏敏感度和定位的精度。

## 6. 主要结论与发现

1. **Enoki-LLM 是细粒度定位的最优选择**：在 HalluEntity 上较最佳基线（LettuceDetect-large）提升 **+15.3 AUPRC**；在 MuSHROOM 和 PsiloQA 上分别以 **52.07 和 71.15** 的 Span Coverage F1 领先其他显式验证方法。
2. **资源友好版本显著有效**：Enoki-Rule 和 Enoki-Encoder 保留大部分优势，且在推理上比全部基于 LLM 的方法快出**两个数量级**；Enoki-Encoder 更是在 RAGTruth 跨度任务上逼近直接在标注上微调的 LettuceDetect。
3. 跨层级的统一表示将"可解释声明级验证"和"精确定位"交织在一处，单一流程替代分离式的声明→对齐→验证流程。
4. 定义幻觉概率时，将 "neutral" 与 "contradiction" 合并降低了漏检风险；同时对长上下文做 max-entailment 聚合有效。
5. 在句子级粗粒度判别中，Enoki 与强显式验证竞争保持竞争力，但并非稳定优于全部基线的绝对胜者（有些任务上 FactOWL/Claimify 结合 Prompt 可能更好）。
6. 分解质量优于验证器选择带来的影响更大：采用 Qwen3.5-9B 的验证器提升了 MuSHROOM/RAGTruth，但在 PsiloQA 有小幅回退，进一步印证分解与验证模块均可独立优化、两者共同决定最终效果。

## 7. 优点

- 方法设计创意与实用性兼顾：
  - 以 OpenIE（文本锚定的关系事实）与增量细化作为统一表示，创造性地消解了 "claim级可解释性 vs span级定位" 的对立，结构清晰。
  - 可配置的提取器家族（LLM、编码器、规则）使得计算预算可伸缩，极易在工程上落地。
- 技术上精细大胆：
  - 将 DETR 式匈牙利匹配引入I GL 训练，克服了增量多行生成固有的行序不确定问题。
  - 采用严格、细粒度、自包含的事实细化准则，显著优于开放类 OpenIE (MinIE等）的泛化输出粒度。
  - 实际效应在长上下文里设计分块 + max 策略，保证可扩展验证。
- 实验设计周全且提供新资源：
  - 引入大尺度 EnokiQA 长问答双粒度标注集，答案与证据平均长 5.7k 和 15.8k 字符，明显更长、更真实。
  - 对比时尽量校准阈值，报告注意了偏差，且探讨了标注噪声（对粗粒度标注提出更合理的 SCF1 metric）。
  - 提供多模型、多生成器、多层级分析，避免单一模型的偶然性。

## 8. 不足与局限

- **对事实分解的强依赖**：只验证被抽取出来的事实；若遗漏必要命题、错将多事实合并或产生过宽/过窄的论元，后续无法补救。这也是所有显式验证法的内在瓶颈。
- **增量投影结构的局限**：只有当同一个事实的重述子事实大致嵌套时，把未执行部分分配到局部 delta 才比较合理。在多部分同时虚假或错误非局部交互时，span 可能比人类手动标注的更宽泛或不够精确。
- **句子级运作框架**：跨句语言现象（前指、省略、语段归属）处理有限；虽然引入 FastCoref 去上下文化，但在部分数据集上效果不升反降，问题未彻底解决。
- **验证器校准敏感**：最终结论依赖 NLI 验证器的校准与稳健性；一个脆弱的验证器，即使事实分解得再好也会引发错误的 claim/span 输出。
- **评测与公平性边界**：
  - 未披露 GPU 型号/训练时长等硬件细节，复现与效率比较受到限制。
  - 在句子级数据集 ANAH / Factcheck 上的表现弱于强隐式直接 LLM 验证法，说明该框架更适合"精确错误定位"而非绝对事实性分数的任务。
  - MuSHROOM 无训练子集且所有方法的阈值固定为 0.5，对各系统的可比较性可能有偏差影响。
- **局限性声明坦诚**，不过，在长答案/长证据环境下，EnokiQA 的人工标注只选取 100 个样例验证可信度（自动标注的 F1 0.867 句子级、0.569 span 级），更大范围的一致性仍需研究确认。
