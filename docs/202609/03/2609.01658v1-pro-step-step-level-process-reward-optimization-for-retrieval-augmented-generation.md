## 摘要
检索增强生成通过将响应基于外部知识来增强大型语言模型，但多跳推理仍然容易受到错误传播的影响，其中早期的检索失败会混淆后续步骤。标准的基于结果的优化仅奖励最终答案，使得中间的检索和推理错误无法被检测。虽然现有的基于过程的方法引入了步骤级信号，但它们仍然根据最终答案对每个步骤进行评分，从而奖励了虚假的成功，即存在缺陷的检索偶然产生了正确答案。RAG中的步骤级监督要求在每个步骤同时评估逻辑有效性和证据基础。我们引入了PRO-STEP：我们训练一个生成式PRM来评估这两个维度，采用PRM引导的值树搜索来构建对比有效步骤与有缺陷步骤的偏好对，并通过步骤级直接偏好优化来优化策略。在单跳和多跳QA数据集上的实验表明，PRO-STEP在五个基准上取得了最佳的平均EM和F1。代码、模型和训练数据可在https://github.com/keemminnke/PRO-Step公开获取。

## Abstract
Retrieval-Augmented Generation enhances Large Language Models by grounding responses in external knowledge, but multi-hop reasoning remains vulnerable to error propagation, where early retrieval failures confound subsequent steps. Standard outcome-based optimization only rewards the final answer, leaving intermediate retrieval and reasoning errors undetected. While existing process-based methods introduce step-level signals, they still score each step against the final answer, rewarding spurious successes where flawed retrieval coincidentally produces the correct answer. Step-level supervision in RAG requires evaluating both logical validity and evidential grounding at each step. We introduce PRO-STEP: we train a generative PRM that evaluates both dimensions, employ PRM-guided value tree search to construct preference pairs contrasting valid steps against flawed ones, and optimize the policy via step-level Direct Preference Optimization. Experiments on single and multi-hop QA datasets demonstrate that PRO-STEP achieves the best average EM and F1 across five benchmarks. Code, models, and training data are publicly available at https://github.com/keemminnke/PRO-Step.

## 一、核心问题与整体含义（研究动机与背景）

检索增强生成（RAG）通过引入外部知识源来缓解大模型幻觉问题，但在**多跳推理**场景中仍面临一个关键挑战——**错误传播（error propagation）**：早期步骤的检索失败、查询不精确或文档不相关，会持续污染后续的推理与检索决策，最终导致整体答案错误。

已有方法存在的问题链条如下：

- **基于结果的强化学习**（如 Search-R1、R1-Searcher）：仅以最终答案正确性作为奖励信号。问题有二：
  - **稀疏性**：模型必须在完成完整推理链后才能获得反馈，样本效率低；
  - **无法定位中间错误**：早期检索失误未被惩罚，会沿推理链传播放大。
- **现有过程奖励方法**（如 ReasonRAG、StepSearch）：虽然引入步骤级信号，但**仍以最终答案的 F1 作为步骤评分依据**，因此会奖励“虚假成功”（spurious success）——即中间检索或推理虽然有缺陷，但碰巧最终答案是对的。它们缺少对每一步**逻辑有效性**与**证据锚定（evidential grounding）**的双重检验。
- **通用 PRM**（如 VersaPRM、Qwen-Math-PRM）聚焦数学等形式化推理域，无法验证回答是否真正植根于检索文档，在 RAG 场景中甚至不如多数投票。

PRO-STEP 的核心主张是：**RAG 中的步骤级监督必须同时评估两个维度——每一步的逻辑合理性和对检索文档的事实锚定**，且不能以最终答案作为步骤正确与否的判据，否则无法滤除“带病正确答案”。

## 二、方法论：核心思想与技术细节

PRO-STEP 是一个**两阶段框架**：

### 阶段一：过程奖励建模（Process Reward Modeling）

1. **轨迹生成**
   - 将 RAG 建模为策略模型 πθ 与外部搜索引擎 E 之间的**多轮交互**；
   - 模型在 `<think>` 内推理，需要外部事实时发出 `<search>`，系统截停生成、执行检索并将结果以 `<documents>` 追加回序列，循环直至输出 `<answer>`；
   - 从 2,000 题（HotpotQA、MuSiQue 各 1,000）采样 16 条轨迹/题，过滤后保留 **31,728 条轨迹**。

2. **步骤标注**
   - 使用 **QwQ-32B** 按六条标注准则（R1 实体/关系、R2 搜索、R3 推理、R4 回答、R5 恢复、R6 过度自信）为每一步生成**理由 vt 和二元标签 rt ∈ {0,1}**；
   - 与以往丢弃错误后所有步骤的做法不同，PRO-STEP **保留完整轨迹**，因为模型可能通过后续修正查询从局部错误中恢复。

3. **生成式 PRM 训练**
   - 以 DeepSeek-R1-Distill-8B 初始化 PRM πψ，训练目标为最大化联合对数似然：
     ```
     L_PRM = −E[ log πψ(vt | q, s≤t) + log πψ(rt | q, s≤t, vt) ]
     ```
   - 推理时先让 PRM 生成 rationale，再输出二值标签：
     ```
     r̂(st) = argmax πψ(r | q, s≤t, vt)
     ```

### 阶段二：策略优化（Policy Optimization）

1. **PRM 引导的值树搜索（Value Tree Search, VTS）**
   - 类似 AlphaGo Zero：每个节点代表状态 st，动作是从 πθ 采样下一步；
   - 树的构建通过 UCB 选择、扩展和反向传播完成；
   - **非终止节点**价值直接由 PRM 给出：
     ```
     Q(st) = r̂(st) · γ^d(st)
     ```
     （γ=0.9 惩罚长轨迹，d 为节点深度）
   - **终止节点**奖励为深度折扣 F1：Q(sT) = F1(sT, y*) · γ^d(sT)。

2. **偏好对构建**
   - 对每个父节点的子节点按价值函数排序：
     ```
     V(s) = Q̄(s) + α · r̂(s)   （α=0.3）
     ```
   - 对任意差值超过 δ 的兄弟节点对，高者为 chosen、低者为 rejected；
   - 该机制能**主动筛选出“带病正确”的轨迹**（从训练材料中剔除），这是区别于 ReasonRAG、StepSearch 的关键。

3. **步骤级 DPO**
   - 定义隐式效用：
     ```
     uθ(x, yt) = β log [ πθ(yt | x, y<t) / πref(yt | x, y<t) ]
     ```
   - 最小化 DPO 损失（计算时 mask 掉 `<documents>` 块）：
     ```
     L_DPO = −E[ log σ(uθ(x, y_wt) − uθ(x, y_lt)) ]
     ```

## 六、主要结论与发现

1. **总体性能**：PRO-STEP 在 5 个基准上取得最高平均 EM（34.5）和 F1（44.1），相对 Search-R1（结果奖励 RL）平均提升 2.5 EM / 3.4 F1；在 2WikiMultiHopQA 上提升高达 9.2 EM / 8.9 F1；
2. **PRM 的必要性**：去掉 PRM 后平均 EM 从 34.5 降到 32.7，多跳数据集降幅最大，说明**单纯最终结果无法惩罚虚假中间推理**；
3. **DPO 优于 SFT 与 KTO**：对比式信号对步骤级学习效果最好；KTO 使用未配对二元标签反而劣于 SFT，说明**相对对比比绝对标签更重要**；
4. **RAG 专属 PRM 的必要性**：在轨迹重排中，通用 PRM（VersaPRM）与数学 PRM 随候选池扩大表现下滑甚至低于多数投票；PRO-STEP 的 PRM 在 WMV 和 BoN 下表现稳定上升；
5. **样本效率**：以 5k seed questions 超越 Search-R1 的 17 万训练实例，证明密集步骤反馈显著缓解了奖励稀疏问题；
6. **错误恢复能力**：在“首次检索失败但后续成功恢复”的子集上全面优于 Search-R1（EM 和 F1），且恢复发生更早、恢复集更小；
7. **泛化性**：跨模型家族（Llama-3.1）、跨规模（3B/7B）、跨对齐状态（Base/Instruct）均保持增益；
8. **失败模式确认**：IFBC 率（正确回答中的中间缺陷轨迹比例）明显低于基于最终结果的对照与基线（26.8% vs. 40.3%），直接证明 PRM 过滤了虚假过程。

## 七、优点

1. **问题定义精准**：清晰地区分了“针对最终答案评分的过程方法”（现有方法）与“真正评估步骤逻辑+证据有效性的过程监督”（PRO-STEP）；
2. **两阶段设计自洽**：生成式 PRM（输出 rationale + 标签）→ 引导 VTS → 构造偏好对 → 步骤级 DPO，每一环都有明确设计动机；
3. **主动对抗“虚假成功”**：用步骤级 PRM 评估而非最终 F1 来筛选偏好对，直接消解了过程奖励中的常见偏误；
4. **保留完整轨迹**：意识到 RAG 中的恢复能力（修正查询）意味着局部错误不等于整条链条无效，因此在注释阶段不丢弃错误后的步骤；
5. **开源性**：全流程使用开源模型（DeepSeek-R1-Distill-8B 的 PRM、QwQ-32B 标注器），无 GPT-4o 之类的闭源 API 依赖，可复现性强；
6. **透明度高**：记录了失败的扩充策略（基于 PRM 反馈的重生成导致性能大幅降低及其分布漂移诊断），并呈报不显著结果；
7. **实验多角度交叉验证**：主结果之外有恢复分析、IFBC 量化、k 消融、统计显著性检验、人工与前沿模型标注审计；
8. **样本效率显著**：5k 训练题达到与 170k 量级训练方法相当或更好的效果。

## 八、不足与局限

### 方法本身的局限

- **QwQ-32B 标注质量上限**：PRM 训练标签质量受限于 QwQ-32B。虽然 500 例审计显示与 Claude Opus 4.7 的 Cohen's κ=0.61（基本一致），但推理类步骤的标注一致性很低（κ=0.12），且 QwQ 略偏宽松；
- **PRM 的错误传播限制**：训练中 PRM 的二元标签本身可能有噪声，且 VTS 中 Q(s) = r̂(st)·γ^d 的设定使 PRM 标签在离线构造数据时是唯一的步骤级信号来源，PRM 系统性错误的后果未被充分研究；
- **生成式 rationale 信息未被利用于策略优化**：虽然 PRM 生成文本理由，但 DPO 阶段仅使用二值标签构建偏好对，rationale 只充当中间产物，没有直接输入策略或用于构造更丰富的偏好信号。

### 实验覆盖的局限

- **基线的公平性受限**：Self-RAG 与 AutoRAG 使用不同骨干（Llama-2-13B、Llama-3-8B），模型规模与家族不一致会带来混淆；
- **Bamboogle 样本量过小**（125 测试题）：与 ReasonRAG 的差异 p=0.66，统计上不显著，作者虽做了披露但主表仍突出显示该项收益；
- **MuSiQue 上不如 StepSearch**（−1.3 EM）的归因存在不确定性——是否纯因训练数据规模（5k vs. 19k），未做在同一数据规模下的对照；
- **只评估了 QA 任务**，未涉及多文档问答、长文本生成、事实验证等其他典型 RAG 场景；未分析对推理链长度、查询重写质量的细节影响；
- **检索器固定为 BGE-base**，未检验在不同检索器（如 BM25、ColBERT、混合检索）下的稳定性；
- **VTS 超参数敏感性**：虽报告了 α 的消融与分支因子消融，但对树的迭代次数（64）、探索常数 c 等未做敏感性分析；
- **领域偏置**：训练数据主要来自 Wikipedia 域的多跳 QA，迁移到时效性要求高或非百科域时效果未知。

### 推理效率的局限

- 训练阶段 VTS 每问题 64 次迭代、每次迭代扩展 3 个子节点等流程的**推理开销未量化**（时延、token 消耗）；
- 测试时是单模型单次解码，但这**主要是数据构造阶段的计算投入**，即训练数据制作成本较高——论文未报告这部分总 GPU 小时数。

### 其他

- 论文声称 DPO 缓解了奖励稀疏，但 DPOP 对的构造依赖 VTS 中大量 rollouts，整体数据管道成本并不低，只是避免了在线 RL 的交互成本；
- 检索步数分析（图 5）只报告了累计 F1，未与基线在不同步数上限下对比，不能确认该自适应能力是否优于其他 RL 方法（如 Search-R1 是否会在 1 步内过早截断）。

**总体评价**：PRO-STEP 的问题定位、方法设计和证据链条在 RAG 过程监督方向有明显贡献，实验规模与附带的诚实分析（失败的扩充策略、不显著结果、统计检验）都体现了较高的研究规范，但在任务多样性、基线与骨干一致性和部分报告的工程细粒度方面仍有提升空间。
