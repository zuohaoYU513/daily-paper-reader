## 摘要
专家级金融问答既需要基于事实的验证以捕捉数值幻觉，也需要满足监管合规的审计轨迹，而标准单次检索增强生成（RAG）系统不具备这些特性。我们通过自我改进的检索增强生成（Self-Improving RAG）框架向这一目标迈进了一步，该框架将文档问答分解为三个专门智能体（检索、推理和评判），并由一个具备反馈驱动自我修正能力的编排器进行协调。当评判智能体将答案评分低于动态阈值时，系统会触发重试并升级策略：更广泛的检索、更精细的提示以及更宽松的接受标准。我们在FinanceBench（SEC文件问答）上进行了评估，自我改进的检索增强生成实现了86%的甲骨文引导准确率（衡量与标准答案的一致性），同时具有36.4%的“复活率”（Lazarus Rate），即通过有针对性的重试恢复了近四成的初始错误答案。一个关键发现是，固定的检索流程配合评判驱动的重试，无需动态路由即可取得强劲结果，同时提供完全的可解释性。每一步决策都记录有置信度分数，从而支持受监管金融应用所需的审计轨迹。

## Abstract
Expert-level financial question answering requires both grounded verification to catch numeric hallucinations and audit trails for regulatory compliance, attributes that standard single-pass RAG systems lack. We take a step toward this goal with Self-Improving RAG, a framework that decomposes document QA into three specialized agents (Retrieval, Reasoning, and Judge) coordinated by an orchestrator with feedback-driven self-correction. When the Judge Agent scores an answer below a dynamic threshold, the system triggers retry with escalated strategies: broader retrieval, more careful prompting, and relaxed acceptance criteria. We evaluate on FinanceBench (SEC filing QA), where Self-Improving RAG achieves 86% oracle-guided accuracy (measuring agreement with gold answers) with a 36.4% Lazarus Rate, recovering nearly 4 in 10 initially incorrect answers through targeted retry. A key finding is that a fixed retrieval pipeline with judge-driven retry achieves strong results without dynamic routing, providing full interpretability. Every decision is logged with confidence scores, enabling the audit trails required for regulated financial applications.

## 1. 论文核心问题与整体含义

- **研究背景**：检索增强生成（RAG）已成为知识密集型问答的标准范式，但在金融等高风险领域，标准单次管道存在一个致命缺陷——无法识别和纠正自身错误。金融分析师查询 SEC 文件中的营收数据时，单次 RAG 系统返回一个错误答案后没有任何校验机制，而金融从业者认为“错误的答案比没有答案更糟”。
- **围墙花园约束（Walled Garden Constraint）**：金融应用要求检索必须严格限定在授权文档语料内，数据治理策略禁止回退到外部网络搜索。这消除了 CRAG 等系统依赖的常见恢复机制，要求设计全新的自我纠错路径。
- **金融领域三大特有挑战**：
  1. 对表格和财务报表的数值推理；
  2. 需要对财年、报告期进行时间过滤；
  3. 代码、子公司、公司更名之间的实体消歧。
- **核心研究问题**：如何在封闭语料约束下，构建一个具备自我纠错能力、可验证、可审计的金融级 RAG 系统？

## 2. 提出的方法论：Self-Improving RAG

- **总体架构**：将文档问答分解为三个专门智能体（检索、推理、评判），由一个编排器（Orchestrator）协调，实现反馈驱动的自我纠错。
  - **Retrieval Agent（检索）**：分析查询、抽取实体、选择检索管道，随着尝试次数递增进行升级（k=10 → 20 → 30，最终尝试启用 RSE 段合并）。
  - **Reasoning Agent（推理）**：基于检索证据生成带引用的答案，并随尝试次数在三种提示策略间升级（STANDARD → CONSERVATIVE → DETAILED）。
  - **Judge Agent（评判）**：评估答案质量（基础性 grounding、完整性 completeness、数值忠实度 numeric faithfulness），决定接受或请求重试。
- **动态阈值机制**：`τ_t = max(τ0 − λ(t−1), τ_min)`，初始阈值 τ0=0.5，衰减率 λ=0.1，下限 τ_min=0.3。这体现精确率-覆盖率权衡：早期尝试要求高置信度，后期接受边际答案。
- **质量向量与聚合**：`U_t = w_g·μg + w_c·μc + w_n·μn`，金融场景下权重设为 wn=0.5（数值）、wg=0.3（基础性）、wc=0.2（完整性）。
- **数值忠实度验证（式 6）**：`μn(a,E) = 1[|N(a) \ N(E)| = 0]`——要求答案中每个数值都必须在检索证据中有显式支持，以捕捉“近似错误”的数值幻觉。
- **算法流程（Algorithm 1）**：
  1. 维护历史最佳答案（best answer），确保重试不会降低输出质量；
  2. 每次尝试执行“检索→生成→评分”循环；
  3. 若评分低于当前阈值，则触发升级重试（更广检索、更谨慎提示、更宽松阈值）；
  4. 预算耗尽后返回历史最佳答案。
- **收敛性保证（Proposition 1）**：系统失败概率随尝试次数呈乘法衰减：`P_fail = Π_{t=1}^{T} P(D_t = 0 | S_{t−1})`，证明重试策略的累积恢复能力。
- **审计优先设计**：每个智能体决策均记录来源、置信度分数和推理轨迹，满足受监管行业的合规审查。

## 6. 主要结论与发现

- **主结果**：Self-Improving RAG 在 FinanceBench 上达到 86% oracle 引导准确率，较单次 RAG 基线（53%）相对提升 +62.3%。
- **Lazarus Rate = 36.4%**：在 33 个盲评判触发重试的问题中（占总数的 22%），12 个被成功纠正，即近 4 成初始错误答案得到恢复。

- **消融发现**：提示升级贡献最大（−10.6%），说明在重试时鼓励更仔细的推理比单纯扩宽检索更有价值；重试预算至关重要（B=1 vs B=2 下降 −25.5%）。
- **问题类型差异**：领域相关问题受益最大（+81.1%），因为这类问题通常首次回答不完整，最需要自我纠正。

## 7. 优点

- **方法设计亮点**：
  - 多代理分工清晰，每个智能体有明确职责和升级策略，诊断细化到检索或推理层面的失败根源；
  - 历史最佳答案保留机制保证“重试永不劣化”，这对实际部署中的信任建立至关重要；
  - 数值忠实度验证（式 6）以严格集合覆盖捕捉数值幻觉，是金融场景的定制化设计；
  - 审计日志完整记录每个决策和置信度，直接响应受监管行业的合规需求。
- **实验设计亮点**：
  - 诚实披露 Oracle-Guided 与 Deployment 两种评估模式的显著差距，承认盲评判是部署的主要瓶颈；
  - 反直觉结果（去除确定性验证反而提升）得到了深入归因分析——过度敏感的数值匹配导致语义正确但格式不同的答案被误判。

## 8. 不足与局限

- **盲评判可靠性瓶颈**：部署模式仅 31% 接受率，与 oracle 模式（86%）差距巨大。无金标准下的质量估计仍是核心未解决问题。
- **延迟成本**：重试触发时延迟 15–25 秒（单次管道仅 5–8 秒），仅适合分析师辅助工具，不适用于实时应用。
- **数值精确匹配未改善**：自我纠错主要恢复语义不完整性，而非提取/计算层面的数值精确性。
- **统计功效不足**：n=150 样本量导致消融差异不显著，作者自身也承认 −10.6% 与 +2.1% 等结果应在置信区间内谨慎解读。
- **确定性验证异常**：过度敏感的数值匹配会误伤格式不同但语义正确的答案（如“$394.3 billion” vs “$394,300 million”），触发不必要重试，反而引入新错误。
- **外部对比不足**：与 Self-RAG、CRAG、Adaptive-RAG 等仅做了定性对比（表 1），未在相同实验条件下进行定量基准测试。
- **错误类型上限**：28% 的失败来自检索上限（语料中缺失信息），说明系统无法超越授权语料库的覆盖范围——这既是合规约束（围墙花园），也是性能天花板。
