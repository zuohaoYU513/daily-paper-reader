## 摘要
学术同行评审规模的日益扩大，推动了使用大型语言模型（LLMs）作为评审辅助工具，但LLMs可能会生成流畅但缺乏依据的陈述，从而削弱评审的可靠性。现有的幻觉基准并非为同行评审而设计，因为同行评审中的验证需要将陈述依据于长篇技术论文。我们提出了HalluPeer，一个用于检测科学同行评审中幻觉的基准，提供了论文内容、人工撰写的评审以及注入幻觉的评审的对齐三元组，并标注了检测、分类和定位信息。我们的流程引入了针对同行评审的幻觉分类法，识别评审上下文，并通过自动化过滤注入幻觉。在12K篇论文和38K条评审上的实验表明，现有检测器难以将幻觉与合法批评区分开来，而对真实评审的评估则表明，HalluPeer定义的幻觉模式确实存在于真实同行评审中，这凸显了基于来源的验证的迫切需求。我们的项目页面可在https://github.com/Lin-TzuLing/HalluPeer.git找到。

## Abstract
The growing scale of academic peer review has motivated the use of Large Language Models (LLMs) as review assistants, yet LLMs can generate fluent but unsupported claims that undermine review reliability. Existing hallucination benchmarks are not designed for peer review, where verification requires grounding claims in long, technical papers. We introduce HalluPeer, a benchmark for detecting hallucinations in scientific peer reviews, providing aligned triples of paper content, human-written reviews, and hallucination-injected reviews, annotated for detection, classification, and localization. Our pipeline induces a peer-review-specific hallucination taxonomy, identifies review contexts, and injects hallucinations with automated filtering. Experiments on 12K papers and 38K reviews show that existing detectors struggle to separate hallucinations from legitimate critique, while evaluation on authentic reviews demonstrates that HalluPeer-defined hallucination patterns occur in real peer reviews, highlighting the critical need for source-aware verification. Our project page can be found in https://github.com/Lin-TzuLing/HalluPeer.git

## 2. 论文提出的方法论

### 2.1 核心思想概述
通过两个原则指导基准构建：**覆盖科学失败模式**（coverage of scientific failure modes）与**控制错误类型与上下文**（control over error types and contexts）。构建流程包含 "评审特定层级幻觉分类法 → 抽取评审句子与方面标签 → 模板筛选 → LLM 受约束编辑注入 → 语义验证过滤" 几个部分。

### 2.2 幻觉分类法构建（Top-Down Taxonomy Construction）
- **树形结构定义**：分类法是一棵有根树，节点 v = ⟨h_v, δ_v, p_v, C_v⟩，其中 h_v 为幻觉概念名称，δ_v 为操作化描述，p_v 为父节点，C_v 为子节点集合。叶节点提供细粒度的显式注入指令，同时作为细粒度评测标签。
- **第一层粗粒度锚点**：借鉴已有分类工作（HalluMeasure），初始化 9 个粗粒度语义锚点：Number、Entity、False Concatenation、Attribution Failure、Overgeneralization、Reasoning Error、Hyperbole、Temporal、Context-based Meaning Error。
- **LLM 引导的递归分解**（Algorithm 1，DFS）：
  - 使用 `EXPAND_M` 让 LLM 将一个父概念分解成多个子概念；使用 `DESCRIBE_M` 为子概念生成操作化定义。
  - 递归终止条件：达到预设最大树深度；或 LLM 返回空列表（该概念在当前深度已不可再分）。
  - 强制约束：MECE（互斥且集合完备）风格的兄弟划分；基于具体同行评审场景；同层粒度一致；当父概念已原子化时返回空列表。
- **多模型集成与专家精炼**（Ensemble and Expert Refinement）：
  - 使用 Qwen3-32B、Llama-3.3-70B 和 Mistral-Small-3.1-24B 独立生成分类树，Qwen3-32B 生成的树为主结构。
  - 第 1 阶段：通过 BAAI/bge-large-en-v1.5 嵌入跨模型计算余弦相似度（阈值 > 0.8），保留跨模型共识节点。
  - 第 2 阶段：全局重叠识别，多 LLM 共识从约 86,800 个候选节点对过滤出 434 个高重叠对。
  - 第 3 阶段：人类专家人工审查合并或保留决定。
  - 最终分类树包含 265 个节点，其中 205 个叶节点（98% 在深度 3），最大深度为 3。

### 2.3 HalluPeer 构建管道
- **数据收集**：从 OpenReview 获取 ICLR（2019–2024）与 NeurIPS（2021–2024）记录；每年每会议均匀抽样 1,200 篇论文，共 12,000 篇论文、38,063 条评审、超过 102 万个评审句子、总计 1,014.9 万个幻觉模板。
- **评审过滤**：使用 LLM 过滤器将每条评审与对应 meta-review 比对，只保留高置信度、与 meta-review 对齐（主线被 meta-review 采纳）的评审，降低以本身不可靠的评审作为注入源的风险。
- **方面标签标注（Aspect Tagging）**：用 Llama-3.3-70B 对每条评审句子进行零样本方面标签标注（如 Novelty、Evaluation、Clarity 等），以用作注入约束——注入的幻觉类型需与句子角色兼容（如 Number 相关的扰动优先注入 Evaluation 句子，而不注入 Clarity 句子）。
- **模板构建（Injection Template Construction）**：
  - 每个句子 s 与叶节点 v 配对构成模板 T_{s,v} = (s, a_s, δ_v, π_v)。
  - 为避免全对全的不可解组合，先做粗粒度筛选（coarse screening），只对一句子可适用的第一层概念构建细粒度模板。
  - 再用基于 LLM 的兼容性检查 `CHECK_M` 过滤出可行模板集。
- **自动注入管道（Automated Injection Pipeline）**：
  - 对每个可行模板，LLM 注入器 `INJECT_M(sentence, δ_v)` 在保持流畅的前提下改写句子，引入指定幻觉。
  - 事后验证器 `VERIFY_M(s, s̃)`：测试注入后的句子与原句是否"语义等价"（标准参考 SECA 的定义），若语义等价则视为注入失败并丢弃。

### 2.4 评测任务形式化
- **任务 1：幻觉检测**——二分类，分评审级与句子级：判断评审/句子是否包含幻觉。
- **任务 2：幻觉类型分类**——给定被判定为幻觉的句子和论文证据，从 9 个粗粒度类别中预测一个幻觉类型。
- **任务 3：幻觉定位**——跨度识别：给定评审，标出对应幻觉内容的 token 级边界。

  8. 分类法大量生成细节和过滤统计（分类树节点统计、对约 86,800 个候选节点对的成对重叠识别等）。

- **充分性与公平性评价**：
  - **优点**：实验矩阵相对完整，每个结论都有交叉验证支撑；在跨 venue 与跨生成器两个维度均增加了量化证据；真实评审验证部分使用未参与训练的独立人工标注集，避免了合成数据"自说自话"的可能。
  - **可改进之处**：真实评审验证集只有 20 个正例，统计置信区间较宽；跨生成器消融的注入器/验证器同为 Mistral/Llama 系，未见与 GPT-5.2 系等其他系列生成器的交叉测试。论文未报告微调时每个 epoch 的确切步数与总训练时长，对复现的时间成本估计会造成障碍。

## 6. 论文的主要结论与发现

- **现有专用验证器泛化差**：HHEM、True-NLI、seNtLI、RefChecker 在评审级上接近随机表现（MCC ≤ 0.03–0.04），无法将科学评审中无依据声明与合理批评区分开。因为从一般 RAG/NLI/事实一致性数据中习得的验证能力不适用于需要长论文跨节多跳推理的评审场景。
- **零样本 prompting 能力不足**：前沿 LLM 在句子级有一定表现，但评审级一致性和全局聚合显著较差；类型分类特别是评审级分类（最佳 Macro-F1 仅 0.19）几乎不可用；哪些类别具有显式词汇线索（Entity/Number）相对较好，需要语义聚集或多跳推理的类别（Context-based Meaning Error、Hyperbole、Temporal）表现接近零。
- **领域特定微调效果显著**：即使紧凑的 Qwen2.5-3B 也全面超过 GPT-5.2、Llama-3.3-70B 等零样本前沿模型；Qwen3-32B（fine-tuned）在 NeurIPS 2024 上达到评审级 F1 0.90、句子级 F1 0.91 与 MCC 0.87，精调显著弥合了语义复杂类别（Hyperbole 从近零提升到 0.72/0.87、Temporal 到 0.48/0.87、Context-based Meaning Error 到 0.56/0.82）的差距。
- **跨 venue 与跨生成器泛化良好**：跨会议迁移任务 1 损失极小（F1 相差约 0–0.04），任务 3 Token-F1 保持 0.91/0.92；跨生成器实验中任务 1 平均 F1 偏移仅 0.01–0.02、任务 2 偏移一般 < 0.05、任务 3 偏移 < 0.02，说明模型学到的是评审幻觉的结构性定义，而非生成器伪迹或 venue 特定写作风格。
- **真实评审存在 HalluPeer 定义的模式**：人工检查发现标注的真实评审错误确实落在分类法的"粗粒度 → 域特定 → 细粒度"路径内（如 Entity/Attribute Substitution、False Concatenation/Method Misattribution、Reasoning Error 的优化方向反置等），证明分类法对真实错误模式有对应性；仅用合成数据训练的 Qwen3-32B 在 1,161 条真实评审上可恢复全部 20 条专家标注幻觉（TPR=100%），同时 FPR=22.1%，可作为一个高召回初筛阶段使用。
- **来源归属仍是核心挑战**：人工检查发现的假阳性主要来自评审者"引用/转述论文本身"的夸张或无依据陈述，即文本看上去是幻觉，实则来自论文而非评审者。这是评审验证系统需要重点解决的方向——区分"评审者生成的幻觉"与"传播了论文已有问题"。
- **结论**：科学评审的自动化审计需要专门的"来源感知验证"（source-aware verification），而非直接套用通用幻觉检测模型。

## 7. 优点

- **任务是真正的新空白**：针对具体科研评审场景设计了"论文锚定验证"的专用幻觉 benchmark，这是既有 QA/摘要/RAG 幻觉基准未覆盖的域。
- **分类法设计细致且系统**：从 9 个粗粒度锚点递归分解到 265 个节点（205 个叶子），用"多模型生成 + 全局重叠过滤（86,800→434 对）+ 专家人工验证"的流程降低单一模型偏置；细粒度叶节点描述达到可直接执行注入的级别。
- **高度可控的数据合成管线**：采用"分类学指令 × 评审方面标签 × 句子内容"三层约束注入，并用粗筛选-细故障兼容检查-事后语义等价过滤做强质检，使正负样本标签更可靠；与 meta-review 对齐的评审过滤机制

- 与 meta-review 对齐的评审过滤机制，进一步保证了注入源（即评审声明）本身的可信度，降低了合成数据中“错上错”的噪声传播风险；同一流程还通过“粗粒度相容性筛选 → LLM 细粒度兼容检查 → 注入后语义等价剔除”三层质检，将标签噪声控制在一个可量化、可解释的范围内。
- **评测形式化程度高，工程落地感强**：将问题拆解为检测、分类、定位三个子任务，并分别定义句子级/评审级、粗粒度/细粒度、Token-F1/Span-F1 等指标，使下游研究者既可以直接复用基准跑分，也可以把模型当作真实评审流中的“初筛器”集成到工作流。
- **实验验证的闭合度高**：不仅做了同分布评测，还补充了跨 venue（ICLR↔NeurIPS）、跨生成器（Mistral/Llama 注入）、真实评审（含 TPR/FPR）三个维度的泛化论证，使“合成数据训练 → 真实场景应用”这条路径的核心风险——数据偏差——得到了正面回应。全文对失败案例也做了人工细读（附录 H），体现了严谨的实证态度。

## 8. 局限与可改进之处

- **真实幻觉正例极其稀缺**：真实评审手工标注子集内仅 20 条幻觉（1.7% 自然流行率），在如此小的正例集上得出的 TPR=100% 虽有意义，但置信区间极宽；若真实幻觉种类未覆盖分类法中的低频类（尤其是语义/上下文类），则高召回结论不一定能外推到长尾场景。理想做法是持续在多个会议/年度的真实评审上累积数千条级正例，或引入主动学习式的定向标注。
- **对“评审者的幻觉”与“论文本身的失真”边界处理得不够彻底**：作者在人工案例分析中承认许多假阳性是评审者忠实复述了论文中本就错误或夸大的说法——此时系统只能判断“是否有论文支撑”，而无法判断“论文支撑本身是否真实”。该问题被提出但没有成为正式的子任务或评测维度；未来可以考虑把“来源锚定”和“事实真实性”分为两级独立评测。
- **分类法深度与发展性受限**：分类树最大深度固定为 3、叶子分布在少数粗粒度主干之下，导致细粒度类别数（205）虽多，但多数由少数几个第一层祖先派生；同时分类法一旦冻结，无法自然演化出新出现的评审错误模式（例如随 LLM 辅助写作风格变化而出现的新型属性错误）。作者未讨论分类树的增量更新机制或低资源细粒度类别的数据增强策略。
- **全流程过度依赖 LLM 判断**：从分类法生成、评审过滤、方面标签、兼容性检查到注入后语义等价验证，几乎每一环都以“另一个 LLM”作为裁判或操作者。虽然作者用多模型共识与人工抽查来缓解，但系统性偏置仍有逐级放大可能；论文未量化每一环节 LLM 判断出错所引入的端到端标签噪声占比。
- **合成数据与真实评审分布仍存在可感差距**：任务 2/任务 3 在合成测试集上的高分数并不能推测真实评审上分类与定位的高性能（真实数据集仅允许测检测 TPR/FPR），即检测之外的两个任务在真实场景中的有效性实际上未被评估。此外正负样本比例由构建流程的注入配额决定，与真实 1.7% 的流行率差距较大，导致实际部署时的校准或阈值调整问题没有正面讨论。
- **定位任务的标注口径偏保守**：Token-F1/Span-F1 的评价基于注入指令所对应的“污染跨度”，但真实书写场景中，一段幻觉话语可能与多个叶节点相关（例如一个句子里既有 Entity 错误又叠加 Hyperbole），标注和评价只取单一标签，可能不利于细粒度多标签场景的后续研究。
- **报告缺少训练与推理成本细节**：仅明确给出单卡 H100、4-bit QLoRA 等硬件配置，却未报告总 GPU 时长、每 epoch 步数、推理 token 成本等，不利于复现者进行成本预估；同样，与 GPT-5.2 等 API 模型对比时也没有披露 API 调用的价格估算，削弱了“可用性”维度的公平比较。

## 9. 个人总体评价（学术价值、实践意义与阅读建议）

- **学术价值**：HalluPeer 是同行评审自动化方向上一个必要且及时的基准。它首次把“幻觉”从通用的机器阅读/事实一致性语境迁移到一个高度依赖领域知识、跨节推理和模糊话语规范的场景里，并通过严格的分类学工程将这一模糊场景操作化。其贡献不仅在于发布数据和 9 类/205 叶的标签体系，更在于给出了“分类法构建 + 受约束合成注入 + 泛化验证”的一套可复用范例。**论文可以作为科学评审 NLP、可信 LLM、来源感知验证三条研究线交叉处的锚点引用。**
- **实践意义**：对于正筹备 LLM 辅助评审的会议/期刊（如 AAAI、ACL 等），本文模型可快速充当“低召回阈值初筛器”来压缩人工复核范围；对平台方而言，HalluPeer 的检测与定位模块也能辅助识别错误引用和凭空捏造的方法描述。但要注意：只在合成数据上评测的分类/定位模块，在真实部署前仍需更大规模的人工校验。
- **潜在风险和值得关注的延伸方向**：1) 将分类法扩展为可更新的“开放式本体”；2) 把“评审失真”与“论文失真”分离为两个正交维度；3) 在多个学科（而不只是 ML 会议）上检验分类法的通用性；4) 与 meta-review 决策结果（accept/reject）做因果关联，探索幻觉对最终录用决策的影响程度。
- **总评**：论文设计严密、实验层次丰富、写作相对透明，尽管存在真实正例稀少和过度依赖 LLM 判断的隐患，其贡献在当前 LLM 介入评审的时点上具有很高的及时性和实用价值。对研究幻觉检测或科研写作分析的研究者来说，是值得精读并可作为后续工作基线的基准工作。
